001. 指针数组与数组指针
1.指针数组是“元素为指针的数组”；数组指针是“指向数组的指针”
2.int *p[N]：指针数组，N 个指针；int (*p)[N]：数组指针，一次跨 N 个元素；
3.[] 先结合是数组，(*p) 先结合是指针。
●int [3][2] 的每个元素是 int[2]，int (*)[2] 的含义是“指向一个 int[2] 数组的指针”，因此可以指向二维数组 int[3][2] 中的任意一行，也可以指向独立的 int[2] 数组。
●int a[static 2] 表示实参至少指向 2 个 int，把这个最小长度契约提供给编译器。
●指针相减有什么前提？ 1两个指针要指向同一数组且类型兼容；2结果是 ptrdiff_t（表示两个指针相减的结果（通常用于同一数组内两个指针的差值），ptrdiff_t d = p2 - p1;），单位是元素个数。跨数组、空指针、函数指针相减都是未定义行为。int (*)[2] 与 int * 类型不兼容，不能混着相减。
002. 回调与用户上下文
回调的标准写法（必须能默写）
"注册时把函数指针和 user_data 成对保存，触发时原样回传，回调内部强转回真实类型。这样同一个回调函数可以服务多个实例，避免使用全局变量。"
/* 1. 定义回调类型：最后一个参数就是 user context */
typedef void (*event_cb_t)(int event_id, void *user_data);

/* 2. 注册接口：函数指针 + 上下文一起存 */
typedef struct {
    event_cb_t cb;
    void      *user_data;
} listener_t;

static listener_t g_listener;
int event_register(event_cb_t cb, void *user_data)
{
    if (!cb) return -1;
    g_listener.cb        = cb;
    g_listener.user_data = user_data;
    return 0;
}
/* 3. 触发时透传上下文 */
static void event_dispatch(int id)
{
    if (g_listener.cb)
        g_listener.cb(id, g_listener.user_data);
}
/* 4. 使用方：上下文通常是"自己的实例指针" */
typedef struct {
    int fd;
    int count;
} my_dev_t;
static void my_on_event(int id, void *user_data)
{
    my_dev_t *dev = (my_dev_t *)user_data;   // 关键：还原上下文
    dev->count++;
}
my_dev_t dev;
event_register(my_on_event, &dev);
1.回调 = 函数指针（做什么）＋ void * 上下文（对谁做）
2.函数指针 typedef 的括号不能省。
3.上下文生命周期必须覆盖回调访问期；异步回调尤其不能传栈变量。
4.接口要约定空回调、空上下文、n == 0 的返回值语义。
5.同步回调返回后即可释放上下文；异步回调要注销并等待。
6.ISR 回调只置标志、发信号量，禁止 malloc / printf / 阻塞
003. 二级指针与资源所有权
1.先算溢出，再申请；用局部指针，成功后再提交。
2.失败不覆盖调用者原指针，旧资源要能继续用。
3.所有权：谁创建、谁释放、恰好一次。
4.malloc(0) 结果实现定义，不可解引用，可 free。
5.二级指针作输出参数，改调用者指针本身，释放后置 NULL 防悬空
6.free 后不置空 → 悬空指针；函数内改不了调用者指针 → 要 void **。
7.链表删除用 Node **，免头节点特判，统一处理头与中间
8.所有权三模型：owned / borrowed / transferred，谁分配谁释放
9.double free：两个指针指向同一块，都以为 owned。二级指针 + 明确所有权约定可避免。
10.const 与二级指针：char ** 不能隐式转 const char **（C 的类型安全规则），要用 const char * const *。
11.argv 的所有权：char **argv 是 borrowed，不要 free(argv[i])。
12.中断上下文：ISR 里不能 malloc/free，所有权在中断和任务间传递要靠静态队列/内存池。
13.DMA buffer 所有权：buffer 在 CPU 与 DMA 之间“转移”，释放前要确保 DMA 不再访问。
14.RTOS 堆：pvPortMalloc/vPortFree必须配对；heap_1 根本不支持 free，所有权模型退化为“只分配不释放”。
004. 嵌入式动态内存策略
1.先算溢出，再申请；用局部指针，成功后再提交。
2.嵌入式慎用 malloc：时间、空间不确定，碎片与 OOM 不可恢复。
3.优先静态分配和栈分配；必须动态时用内存池或固定块池。
4.固定块池 O(1) 分配释放，无外部碎片，嵌入式最常用。
5.TLSF 两级位图实现 O(1) 分配，碎片可控，适合硬实时。
6.FreeRTOS heap_1 只分配不释放，确定性最强，适合初始化期。
7.heap_4 首次适配加相邻块合并，抗碎片，长期运行首选。
8.heap_5 同 heap_4，但支持多段不连续内存区域。
9.内部碎片源于对齐和块头；外部碎片源于反复分配释放。
10.每个 malloc 必须有失败分支，ISR 和热路径禁止动态分配。
11.用统计、水位线、canary、分配钩子做可观测性；MISRA 禁动态内存。
005. 悬垂指针与野指针
1.野指针：未初始化的指针，指向随机地址；定义时立即初始化为 `NULL`。
2.悬垂指针：指向已释放或已失效内存的指针；`free` 后必须置 `NULL`。
3.函数内改调用者指针须用 `void **`；否则只改副本，外部仍悬空。
4.返回局部变量地址即悬垂；栈帧销毁后地址失效，编译器常只给警告。
5.`free` 后不置空 → 悬垂；再次 `free` 即 double free，堆元数据被破坏。
6.释放结构体前先释放其内部指针成员，否则成员指针全部悬垂且泄漏。
7.回调/异步场景：注销回调并等待正在执行的回调返回后，才能释放 `user_data`。
8.链表删除节点后，其他指向该节点的指针全部悬垂；用二级指针统一摘链。
9.`realloc` 成功后原指针可能失效；必须用返回值覆盖，失败时原指针仍有效。
10.调试手段：置 `NULL`、canary 魔数、ASan/Valgrind、分配钩子记录调用点。
006. 栈溢出与堆损坏定位
1.栈溢出检测：栈尾放魔数 canary，函数返回前校验；被改写即溢出。
2.栈水位线：启动时栈填充固定图案，运行后扫描未改区域估算峰值用量。
3.MPU/栈保护页：栈边界设不可访问页，越界立即触发异常，定位最直接。
4.堆越界检测：块尾加 canary 魔数，free 时校验；被改即越界写。
5.堆元数据校验 = 在分配器的管理字段上设"检查点"，让静默的堆损坏在下次分配/释放时当场暴露；MALLOC_CHECK_ 是现成开关，magic 是嵌入式自己动手的版本。
6.ASan/Valgrind（两者都在主机侧定位内存 bug，嵌入式常交叉编译 ASan 复现）：主机侧复现堆越界、UAF、double free。
7.分配钩子记录调用点：重载 malloc/free 存 PC/LR，损坏时回溯谁分配、谁释放。
8.暴露位置 ≠ 写坏位置，free 崩溃不一定是 free 的错。
9.看门狗负责恢复，不负责定位。
10.malloc 的内存在哪个段？堆段（.heap / RTOS 堆区），不是栈也不是 .bss。
007. 函数指针与指针函数、函数指针数组
1.函数指针：指向函数的指针，`int (*f)(int)`；用于回调、驱动注册、状态机跳转表。
2.指针函数：返回指针的函数，`int *f(int)`；注意别返回局部变量地址，否则悬垂。
3.区分口诀：`(*f)` 带括号是函数指针；`*f(...)` 无括号是指针函数。
4.函数指针数组：`int (*a[3])(int)`；按索引调用，替代 switch，O(1) 分派。
5.状态机/命令表常用函数指针数组；越界索引会跳到非法地址，必须检查范围。
6.函数指针可作参数（回调）和返回值（工厂）；typedef 简化签名可读性。
7.函数指针不能隐式转 `void *`；通用函数指针用 `void (*)(void)` 中转。
8.比较函数指针判空再调用；未初始化调用即跳野地址，HardFault 常见根因。
9.`const` 修饰：`int (* const a[3])(int)` 表本身只读，防误改跳转表。
10.中断向量表本质是函数指针数组；启动文件里 `SP` 初值和 `Reset_Handler` 就是它的前两项。
008. 结构体对齐、sizeof(struct)、offsetof 与 container_of
1.对齐规则：
●成员按自身对齐数放置，结构体大小是最大对齐数的整数倍，不足补填充。
●对齐数=编译器默认的对齐数(64位是8)与该成员变量大小的较小值;
Llinux中gcc没有默认对齐数，就是成员自身大小
●如果结构体内有成员长度大于处理器的位数，那么就以处理器的位数作为对齐单位
●#pragma可以编译器的默认对齐数
2. **sizeof(struct) ≥ 成员大小之和**：差额是填充字节，别用成员和估算结构体大小。
3. **调整成员顺序可减填充**：大对齐成员放前、小放后，常能省若干字节 RAM。
4. **offsetof(type, member)**：返回成员相对结构体首地址的字节偏移，编译期常量。
5. **offsetof 实现**：`(size_t)&(((type *)0)->member)`，标准库 `<stddef.h>` 提供。
6. **container_of(ptr, type, member)**：由成员指针减去偏移，反推结构体首地址。
7. **container_of 广泛用于内核链表和驱动框架**：节点内嵌链表，遍历时反推宿主结构体。
8. **`#pragma pack(1)` / `__attribute__((packed))` 取消填充**：用于协议帧、寄存器映射，但可能触发非对齐访问异常。
9. **对齐影响访问**：ARM 非对齐访问可能 HardFault 或降速，packed 结构体成员别直接取地址。
10.**sizeof 是编译期常量、类型为 size_t（无符号）**：与负数比较会隐式转换，循环里 `i < sizeof(x)` 要小心。
009. 手写 memcpy、memmove、strcpy、atoi
#include <stddef.h>

void *my_memcpy(void *restrict dst, const void *restrict src, size_t n);//从 src 复制 n 个字节到 dst，不关心内容，遇 '\0'不停。源和目标重叠时行为未定义（UB）。

void *my_memmove(void *dst, const void *src, size_t n);//同 memcpy，但正确处理重叠：结果等价于先把 src拷到临时缓冲再拷到 dst。

char *my_strcpy(char *restrict dst, const char *restrict src);//把 src 拷贝到 dst，包括结尾 '\0'，遇 '\0' 停。不检查 dst 容量。

int my_atoi(const char *s);//跳过前导空白 → 可选正负号 → 连续数字累加 → 遇非数字停止。无法表示时行为未定义（标准不要求报错）。

010. malloc/free 底层实现与常见分配器
1.malloc 到底做了什么？从分级空闲结构中找一块足够大的 chunk（堆块），切割，标记为已用，返回用户数据指针；不够则向内核要。不是“直接从 OS 拿一块”。
2.free 做了什么？标记 chunk 为空闲，尝试与前后空闲块合并，插回对应 bin；不一定立刻还给 OS（操作系统）。
3.为什么 free 后内存不一定还给 OS？保留在进程的堆里供后续 malloc 复用，避免频繁系统调用；大块（mmap 分配的）会单独归还。
4.为什么实时系统不用 glibc malloc？最坏执行时间依赖堆状态，不可界定；碎片不可控。
5.TLSF（一种专为实时系统设计的动态内存分配器）为什么是 O(1)？两级位图索引直接定位到大小合适的空闲链表区间，分配释放是固定数量的位操作 + 链表操作，与堆大小和碎片无关。
6.fixed-block pool（固定块内存池）和 TLSF（动态内存分配器）怎么选？尺寸可枚举、生命周期稳定、要零外部碎片 → fixed-block pool；需要通用变尺寸堆但要求 O(1) → TLSF。
7.heap_1 和 heap_4 的本质区别？heap_1 只分配不释放，最确定；heap_4 支持释放并合并相邻空闲块，碎片可控但不是 O(1)。
